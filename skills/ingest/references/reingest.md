# Re-ingest procedure

Select legacy candidates by category, Concept connections and secondary-source relationships. Markers include source_locator-only legacy identity, unlinked author strings and absent `## Ingest Notes`; markers are hints, not permission or proof of corruption. Review exact effects before each batch. Batch unit: N items in one category, default 10, with separate batch approval. Each ingest item remains one transaction/commit.

Item key = source_identity (otherwise hash of canonical source_url/source_locator) + operation kind `reingest-v1`; never title. Manifest location: `~/.local/state/secondbrain-skills/reingest/`, outside the vault. Store per-item state (`prepared`, `written`, `committed-local`, `published`), commit SHA, exact written paths, last update time, and each owned path's preimage/postimage existence and bytes. Do not put queue status/digests in Raw. Git log with Ingest-Source/Ingest-Paths trailers is the source of truth; the manifest is resumable bookkeeping.

| Restart situation | Required action |
| --- | --- |
| prepared, before writing | Re-fetch and apply git-provenance pre-write existence/byte guards; obtain fresh approval if preimages drift. |
| written, crash before commit (ARCH-008) | Do NOT repeat the pre-write guard literally or rerun writes. Compare recorded preimage existence/bytes to newly fetched base AND current local existence/bytes to this transaction's recorded owned postimages, for every create/update/delete. Either remote-preimage or local-postimage drift stops/report. Every owned path already staged must hold the intended postimage blob, otherwise stop with index, disk, HEAD and remote untouched. Only then does the transaction run its own index-only `reset --mixed origin/main`, finish exact staging/blob checks and commit once. No hard reset, checkout, rewrite or guessed reconstruction. |
| committed-local, crash before push | If SHA exists locally, retry push only, without reset/re-execution. Missing SHA is a blocker, not permission to recreate. |
| push succeeded before manifest update | Fetch; `git merge-base --is-ancestor <sha> origin/main` establishes publication and corrects manifest to published. |
| same title, different source | Distinguish Ingest-Source trailer and item key, never deduplicate by title. |
| push failed before restart | Preserve committed-local SHA; retry publication only. Non-ff: fetch once, inspect and stop/report conflict; no force push. |

Use git-provenance's lock, no-ahead/no-unrelated-index guards and postimage-only recovery. For Inbox deletion, separately approve the current path and immediately verify current source preimage, captured Original Content extent and full Raw postimage; pause/drain affected writers or prove destination switch. Whole-file Raw/Inbox hash equality and mothership-backup predicates do not apply to this capture move. `--record-deletions` commits only originals that `origin/main` holds with the approved input bytes. Unlinking a never-tracked original changes no tracked path, so there is nothing to record; the helper refuses it as `remote preimage drift`. That refusal is not a 5-C failure, and the Inbox unlink stays valid.

Pilot one representative each: Articles, Videos, Books, Papers, Repositories, Conversations, Mail, KakaoTalk and Clippings, with exact Raw readback and one commit per transaction. A web-book pilot requires a user-selected multi-page source with at least five chapters and two directly fetched chapter URLs before scaffolding. A commercial or offline book instead follows the [books](books.md) file/page locator adaptation: lawfully obtained text, an explicitly approved per-chapter `urn:sha256` or page locator, no chapter URL claimed, and no metadata from a different edition or language. Never reuse a deleted/unavailable book. Pilot success does not authorize the full batch.
